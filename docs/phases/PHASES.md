# Development Phases

## Phase 0: Planning and Spec Governance
Goal: Establish the source-of-truth spec and sprint governance system.
Exit criteria: Spec + sprint docs exist and are cross-linked.

## Phase 1: UI Foundation
Goal: Set up reusable UI primitives, style tokens, motion baseline, and mock data shape.
Exit criteria: App can render themed scene shell and mock data is consumable.

## Phase 2: Homepage Intro Experience
Goal: Deliver immersive full-screen intro with focal `Push Here` CTA and subtitle.
Exit criteria: Intro state matches authored concept and responsive baseline.

## Phase 3: Search Experience V1
Goal: Transition into an artistic search screen with submit-triggered query behavior.
Exit criteria: Intro -> search morph is smooth and mock search functions.

## Phase 4: Archive and Display V1
Goal: Establish first archive display behavior with styled results.
Exit criteria: Users can browse themed result items with coherent interactions.

## Phase 5: Integration Preparation
Goal: Prepare data and asset boundaries for future AniList/Jikan and custom assets.
Exit criteria: Adapter boundaries documented and mock source remains default.

## Phase 6: QA and Polish
Goal: Refine quality, responsiveness, and presentation.
Exit criteria: Practical QA loop complete; polish issues tracked or fixed.
